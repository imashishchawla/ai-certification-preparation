2. Domain Distribution & Question Patterns

D1: Agentic Architecture & Orchestration D1 (≈45 questions)

Largest domain. Covers coordinator-subagent patterns, task decomposition, parallel execution, session management, and orchestration strategies.

Core Patterns Tested:

  • Coordinator-Subagent Pattern: Central coordinator delegates to specialized subagents (web search, doc analysis, synthesis, report generation)
  • Context Isolation: Subagents do NOT inherit parent context — must pass data explicitly
  • Parallel vs Sequential: Emit multiple Task calls in ONE response for parallelism
  • Task Decomposition: Dynamic (adaptive) vs Fixed (prompt chaining) based on predictability
  • Session Resumption: --resume for continuation, fork_session for parallel exploration
  • State Persistence: Structured exports > conversation logs > vector stores for fidelity

🔄 REPEATED QUESTION: Coordinator-Subagent Data Flow

Appears in: set1-q10, set2-q13, set3-q31, set4-q1, set4-q12, set4-q13, set4-q14

The Pattern: Coordinator runs web search → doc analysis → synthesis. How does synthesis get data?

Correct Answer: Coordinator passes structured data/references explicitly (NOT auto-inheritance)

Wrong Answers Always Include: "Subagents share context automatically", "Subagents query each other directly", "Event-driven message queues"

D2: Tool Design & MCP Integration D2 (≈40 questions)

Tool schema design, error handling, MCP server configuration, tool scoping, and tool composition patterns.

Core Patterns Tested:

  • Atomic Operations: Combine check+act into single tool (find_and_book) to prevent TOCTOU races
  • Structured Errors: isError + errorCategory + isRetryable + details (NOT plain text)
  • Transient vs Non-transient: Tool retries 503/timeouts; surfaces 400/401/422 to agent
  • Tool Scoping: allowedTools restricts at runtime (hard enforcement)
  • MCP Scoping: ~/.claude.json (global) + .mcp.json (project-level)
  • Tool Descriptions: Must specify params, output, edge cases, when to use vs alternatives
  • Dynamic Tool Discovery: search_connectors adds matched tools to available set

🔄 REPEATED QUESTION: Scheduling Race Condition (TOCTOU)

Appears in: set1-q3, set4-q25

Scenario: get_available_slots → book_appointment, slot stolen between calls

Correct Answer: Combine into atomic find_and_book_appointment

Distractors: hold_slot tool, richer failure details, retry prompts

🔄 REPEATED QUESTION: Error Handling Partition

Appears in: set1-q2, set1-q5, set2-q3, set2-q31, set2-q40, set4-q20, set4-q17

Correct Pattern: Tool handles transient (503, timeout) with exponential backoff; surfaces non-transient (400, 401, 422) with structured error + customer-friendly message

D3: Claude Code Configuration & Workflows D3 (≈25 questions)

CLAUDE.md hierarchy, hooks, skills, plan mode vs direct execution, MCP resources, session flags.

Core Patterns Tested:

  • CLAUDE.md Hierarchy: User (~/.claude) → Project → Directory (.claude/rules/ with path patterns)
  • @import: Modularize CLAUDE.md with @import for feature-specific rules
  • Hooks: PostToolUse with Edit/Write matcher for deterministic formatting (Prettier)
  • Skills: .claude/skills/name/SKILL.md in project (version-controlled)
  • Plan Mode: Use for unfamiliar code/architecture exploration before implementation
  • Direct Execution: Small, well-understood, isolated changes
  • MCP Resources: Catalog index for large docs (not custom tools or context loading)
  • Session Flags: --resume (continue), fork_session (branch), --session-id (specific)

D4: Prompt Engineering & Structured Output D4 (≈35 questions)

Schema compliance, few-shot prompting, validation-retry loops, batch processing, confidence calibration.

Core Patterns Tested:

  • Schema Compliance: Tool use with JSON schema input parameters > prompt-only JSON
  • tool_choice: "auto" (default, optional), "any" (must call a tool), specific tool name (force one)
  • Few-shot Examples: Best for formatting normalization, granularity, compound phrases
  • Validation Retry: Send validation error back to model for correction (works for format/structure)
  • Retries DON'T Work: Missing information not in source document
  • Confidence Calibration: Compare accuracy at thresholds against labeled validation data
  • Batch API: 50% cost savings, 24hr window, NO multi-turn tool calling
  • Invoice Totals: calculated_total + stated_total + flag mismatch (don't auto-adjust)

🔄 REPEATED QUESTION: Reliable JSON Schema Compliance

Appears in: set2-q5, set2-q15, set4-q21, set4-q35

Correct Answer: Define a tool with the target schema as input parameters

Wrong: Pre-fill brace, detailed prompt instructions, retry on parse failure

🔄 REPEATED QUESTION: Guaranteed Structured Output (tool_choice)

Appears in: set2-q6, set4-q42

Scenario: Multiple extraction tools, unknown doc type, need guaranteed tool use

Correct Answer: tool_choice: "any" with all tools defined

🔄 REPEATED QUESTION: Validation Retry with Error Feedback

Appears in: set2-q14, set4-q16, set4-q31, set4-q32, set4-q40, set4-q43

Pattern: Retry + append validation error → model corrects output

Least Effective For: Missing data not in source (external info)

D5: Context Management & Reliability D5 (≈25 questions)

Context window management, session resumption, progressive summarization, human review calibration, error propagation.

Core Patterns Tested:

  • Progressive Summarization: Keep recent verbatim, summarize older with key conclusions extracted
  • Structured State: Persist order IDs, amounts, statuses separately from conversation
  • Session Resume Strategy: Fresh session + structured summary > full history with stale tool results
  • RAG Context Crowding: Sliding window for RAG results (last 2-3), preserve conversation history
  • Instruction Drift: Reinforce guidelines via user-role messages at breakpoints
  • Confidence Segmentation: Must verify per document-type/field, not just aggregate
  • Amendment Handling: Schema captures multiple values with source location + effective date

🔄 REPEATED QUESTION: Resuming Stale Sessions

Appears in: set1-q14, set2-q30, set3-q31, set3-q46, set3-q60, set4-q44, set4-q45

Scenario: Customer returns hours later, context has stale tool results

Correct: New session + structured summary + fresh tool calls

Wrong: Resume full history with prompt instructions to "prefer latest"

🔄 REPEATED QUESTION: Context Window Management (Progressive Summarization)

Appears in: set2-q29, set3-q39, set4-q44, set4-q45, set4-q50, set4-q52, set4-q53

Correct Pattern: Extract critical structured data → compact reference; summarize general discussion; retain recent verbatim

3. The 12 Most Common Exam Traps

Trap 1: "Parallel Subagents = Faster" — Launching unconstrained subagents without known entry points causes token inflation and fragmented results. Correct: Targeted Grep → incremental trace.
Trap 2: "Ask the User/Engineer" — Prompts explicitly state the user is NEW and doesn't know. Agent must guide THEM. Never punt to user for info they don't have.
Trap 3: "Read Everything Matching Keywords" — Brute force = immediate context saturation. Correct: Grep entry points → follow imports incrementally.
Trap 4: "Subagents Inherit Context Automatically" — FALSE. Subagents start with CLEAN context. Coordinator MUST pass data explicitly in Task prompt.
Trap 5: "PostToolUse Hook Prevents Bad Tool Calls" — PostToolUse fires AFTER execution. Cannot prevent. Correct: Fix system prompt / allowedTools.
Trap 6: "Hardcode Decision Trees / Static Mappings" — Brittle, fails on multi-faceted queries. Correct: Model-driven dynamic partitioning.
Trap 7: "Auto-fetch All Pagination Pages" — Latency spikes + context flood. Correct: First page + total_count + cursor for lazy loading.
Trap 8: "Fake Empty Results for Errors" — Returning empty list for 503 makes agent hallucinate "no results exist". Correct: Retry with exponential backoff INSIDE tool.
Trap 9: "Prompt Instructions Fix Everything" — LLMs struggle with numeric thresholds, consistent boundary evaluation. Correct: Deterministic backend boolean flags (requires_review).
Trap 10: "Resume Full History for Returning Users" — Stale tool results contaminate context. Correct: Fresh session + structured summary + fresh tool calls.
Trap 11: "Sliding Window / Truncation Preserves Key Facts" — Drops critical IDs, allergies, constraints. Correct: Structured state layer + progressive summarization.
Trap 12: "Aggregate Confidence is Enough for Automation" — 97% aggregate can hide 60% on specific doc types. Must calibrate per segment before deploying.

4. Easy Answer Patterns (High-Yield — Learn These First)

✅ Pattern A: "Atomic Tool Design" (Appears 6+ times)

❌ Trap Answers

  • Separate check + book tools
  • hold_slot intermediate tool
  • Richer failure details only
  • Prompt retry instructions

✅ Correct Answer

  • Single find_and_book tool
  • Atomically checks & books
  • Returns confirmation OR alternatives
  • Eliminates TOCTOU race

✅ Pattern B: "Structured Error Responses" (Appears 7+ times)

Always choose the option with:

  • isError: true
  • errorCategory: "transient" | "non_retryable" | "permission_denied" | "not_found" | "validation_error"
  • isRetryable: boolean
  • details: human-readable message with next steps

Never choose: Plain text errors, generic "tool unavailable", retry everything inside tool.

✅ Pattern C: "Tool Use for Schema Compliance" (Appears 4+ times)

When downstream systems reject malformed JSON:

  • Define tool with target schema as input parameters
  • Model calls tool with extracted data
  • Schema enforced at interface level

Beats: Pre-fill brace, prompt instructions, retry logic, regex parsing.

✅ Pattern D: "tool_choice: 'any' for Guaranteed Tool Use" (Appears 2+ times)

Multiple tools, unknown which needed, must guarantee structured output:

  • tool_choice: "any" — forces model to call ONE of the provided tools
  • No classification call needed
  • No consolidation into mega-schema needed

✅ Pattern E: "Few-Shot Examples for Extraction Consistency" (Appears 5+ times)

Inconsistent granularity, compound phrases, implied skills, varied formats:

  • Add few-shot examples showing exact desired behavior
  • Demonstrate: compound splitting, explicit-only, target granularity
  • Beats: constraints, post-processing, schema enrichment

✅ Pattern F: "Progressive Summarization for Context" (Appears 7+ times)

Long conversations, need to preserve key facts:

  • Extract critical structured data (IDs, constraints, allergies) → compact reference
  • Summarize general discussion
  • Retain recent exchanges verbatim

Beats: Sliding window, full summary, vector search replacement, separate API summarization calls.

✅ Pattern G: "Model-Driven Dynamic Orchestration" (Appears 3+ times)

Coordinator deciding which subagents to invoke:

  • Let coordinator use model reasoning to partition work dynamically
  • Beats: hardcoded rules, static decision trees, execute-all-parallel

✅ Pattern H: "Validation Retry with Error Feedback" (Appears 6+ times)

Validation fails with specific error (format/structure):

  • Follow-up request: document + extraction + validation error
  • Model corrects specific issue
  • Works for: format mismatches, structural errors
  • DOESN'T work for: missing external data

Step 2: Apply the "Eliminate Traps First" Method

  1. Cross out any option matching the 12 Common Traps above
  2. Cross out "ask the user", "add more prompt instructions", "retry everything"
  3. Cross out options that violate context isolation (subagents auto-sharing)
  4. Cross out options adding unnecessary complexity (new agents, message queues, classifiers)

Step 3: Match to High-Yield Pattern

If remaining options include a High-Yield Pattern (A-H above), that's your answer. These patterns appear repeatedly because they're the "correct architecture" per Anthropic.

6. Repeated Concepts to Memorize by Heart

These 17 concepts appear across 3+ question sets. Memorize the concept, the correct pattern, and the trap distractors.

🧠 MEMORIZE THESE 17 CONCEPTS

  1. Subagent Context Isolation: Subagents NEVER inherit parent context. Coordinator MUST pass data explicitly in Task prompt.
  2. Atomic Tool Pattern: Combine check+act (find_and_book) to prevent TOCTOU races. Never use hold_slot or separate check/book.
  3. Structured Error Schema: isError + errorCategory + isRetryable + details. Tool handles transient; agent gets non-transient.
  4. Tool Scoping = Hard Enforcement: allowedTools restricts at runtime. Agent CANNOT call tools outside list.
  5. MCP Config Hierarchy: ~/.claude.json (global/user) + .mcp.json (project). Remote=shared→project; local=personal→user.
  6. Hooks for Deterministic Enforcement: PostToolUse with Edit/Write matcher runs formatter. Prompts are probabilistic; hooks are deterministic.
  7. Plan Mode vs Direct Execution: Plan mode = unfamiliar code/architecture exploration. Direct = small, well-understood, isolated changes.
  8. Tool Use for JSON Compliance: Define tool with target schema as input params. Beats prompt-only JSON every time.
  9. tool_choice: "any" Guarantees Tool Call: Forces model to select one tool. Use when document type unknown but structured output required.
  10. Few-Shot > Constraints > Post-Processing: For extraction consistency (granularity, compound phrases, implied content).
  11. Validation Retry Works for Format, Not Missing Data: Send validation error back to model. Fails if info not in source.
  12. Invoice Totals: calculated + stated + flag: Never auto-adjust financial data. Preserve both, flag discrepancy.
  13. Progressive Summarization: Critical structured data (exact) + summarized general + recent verbatim. Beats sliding window.
  14. Session Resume: Fresh + Summary + Fresh Tools: Stale tool results contaminate. Never resume full history with "prefer latest" prompt.
  15. RAG Sliding Window: Limit RAG to last 2-3 queries; preserve conversation history.
  16. Confidence Calibration Per Segment: Aggregate accuracy hides weak spots. Must verify per doc-type/field before automation.
  17. Amendment Schema: Multiple Values + Source + Date: Capture all values with provenance. Don't preprocess/classify/prompt-ignore.

9. Final Exam Day Checklist

  • Read every question TWICE — first for scenario, second for what's actually being asked
  • Identify the DOMAIN immediately (D1-D5) to trigger the right mental model
  • Eliminate trap answers first (12 traps memorized)
  • Match remaining to High-Yield Patterns (A-H)
  • Verify: Does this enforce deterministically? Reduce turns? Preserve fidelity? Scale cleanly?
  • Watch for "NOT" / "LEAST effective" / "MOST reliable" qualifiers
  • For scenario questions: map to archetype (Research, Support, CI/CD, Extraction, Exploration, Workflow)
  • Trust the repeated patterns — they're repeated because they're the certified architecture
    • Pro Tip: The exam heavily favors answers that move enforcement from "prompt instructions" (probabilistic) to "system-level enforcement" (deterministic): hooks, schemas, tool scoping, structured errors, atomic tools, allowedTools. If you see "add instructions to prompt" vs "implement hook/schema/validation", the latter is almost always correct.
