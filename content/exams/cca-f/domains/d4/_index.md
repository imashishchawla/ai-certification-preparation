This domain is about making a request clear enough to produce a useful result and checking that the result meets its contract. Structured output is valuable when another system must consume the response. A good design specifies the required fields, handles missing or invalid values, and avoids relying on prose that a parser must guess at.

## What to practice

- State the task, constraints, and expected output plainly.
- Use a schema when downstream code needs predictable fields.
- Validate responses and plan for correction when the output does not match.
